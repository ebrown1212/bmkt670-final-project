# Seattle Mariners Attendance Prediction
## Field Sources and Data Dictionary

This document identifies the source, population method, and purpose of every field in the PostgreSQL database. The project uses Seattle Mariners home-game data from 2022 through 2025.

## dim_date

One row represents one calendar date.

| Field | Source | How It Is Populated | Purpose |
|---|---|---|---|
| date_key | Calculated in Python | Date formatted as YYYYMMDD | Primary key; connects games and weather |
| full_date | MLB Stats API / Meteostat | Calendar date from the project date range | Matches records by calendar date |
| season | Calculated in Python | Extract year from full_date | Historical season comparisons |
| month | Calculated in Python | Extract month from full_date | Seasonal attendance patterns |
| day_of_week | Calculated in Python | Determine weekday from full_date | Weekday attendance patterns |
| is_weekend | Calculated in Python | TRUE for Saturday or Sunday | Weekend attendance patterns |
| is_holiday | Calculated in Python | Compare dates against U.S. holidays | Holiday attendance patterns |

## dim_team

One row represents one MLB opponent team appearing in the Mariners home-game data.

| Field | Source | How It Is Populated | Purpose |
|---|---|---|---|

## model_predictions

One row represents one Mariners home-game attendance prediction generated by the selected Random Forest model. The table contains predictions for training, validation, and test games.

| Field | Source | How It Is Populated | Purpose |
|---|---|---|---|
| game_id | MLB Stats API / fact_game | Carried from the ML feature table | Primary key and foreign key to fact_game |
| split | ML feature table | Copied from data_split | Identifies train, validation, or test observations |
| actual | Baseball-Reference | Actual attendance from the ML feature table | Compares predictions with actual attendance |
| predicted | Random Forest model | Generated by model/train_model.py | Predicted attendance |
| error | Calculated in Python | Actual attendance minus predicted attendance | Measures prediction error |
| model_name | Python modeling script | Set to random_forest | Identifies the model used |

The modeling script clears and reloads this table each time it runs, preventing duplicate predictions. Validation and test errors provide the most meaningful measures of predictive performance because those observations were not used to train the model.

## ai_summaries

One row represents an AI-generated historical review of one test-game
attendance prediction.

| Field | Source | How It Is Populated | Purpose |
|---|---|---|---|
| game_id | fact_game / model_predictions | Test-game identifier passed to the summary script | Primary key and foreign key to fact_game |
| summary | Claude API | Generated from game features, predicted attendance, actual attendance, and Python-calculated error | Plain-language review for an advertising sales manager |
| created_at | PostgreSQL | Timestamp assigned when the summary is inserted or updated | Records when the summary was generated |

The script uses test predictions only. It stores summaries in PostgreSQL
so the dashboard does not call the API when a page loads.

Rerunning the script updates existing summaries without creating duplicate
game IDs. Each rerun makes new API calls.

Three saved summaries were checked against their source facts.
An earlier prompt produced an incorrect percentage. The revised script
calculates errors in Python and prohibits additional statistics.
Checking three examples does not establish that every summary is correct.
